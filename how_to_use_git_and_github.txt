Vamos lá! Vou criar um guia bem detalhado, claro, e direto para que sua equipe possa trabalhar sem conflitos e com as melhores práticas de versionamento. Este tutorial cobrirá desde a configuração inicial até o fluxo de trabalho colaborativo, com comandos e explicações fáceis de entender, divididos em duas partes: *comandos* e *como e quando usá-los*.

---

## *1. Passo a Passo para Clonar, Configurar e Colaborar com Git*

### *Configuração Inicial para Clonar o Repositório*
1. *Instale o Git*:
   - Certifique-se de que o Git está instalado na máquina local.
   - Para verificar:  
     bash
     git --version
     
   - Se não estiver instalado, baixe e instale o Git: [git-scm.com](https://git-scm.com/).

2. *Configure o Git Localmente*:
   - Adicione seu nome e e-mail para identificar seus commits no repositório:
     bash
     git config --global user.name "Seu Nome"
     git config --global user.email "seuemail@exemplo.com"
     

3. *Acesse o Repositório no GitHub*:
   - Acesse o link do repositório Saludem no GitHub (fornecido pelo líder da equipe ou no seu projeto).

4. *Clone o Repositório*:
   - Copie o link do repositório no GitHub e execute o comando no terminal:
     bash
     git clone https://github.com/SeuUsuario/saludem.git
     
   - Esse comando cria uma cópia local do repositório no seu computador.

5. *Entre no Diretório do Repositório*:
   - Use o comando cd para navegar até a pasta do repositório:
     bash
     cd saludem
     

---

### *Trabalhando em uma Nova Branch*
*Por que criar uma nova branch?*
- Para que cada membro da equipe tenha seu próprio espaço de trabalho isolado.
- Evita conflitos na branch principal (main).
- Permite organizar o trabalho por sprint, funcionalidade ou bug fix.

1. *Crie uma Nova Branch*:
   - Dê um nome descritivo à branch (por exemplo, feature-nome-da-funcionalidade ou fix-nome-do-bug):
     bash
     git checkout -b nome-da-branch
     

2. *Verifique a Branch Ativa*:
   - Certifique-se de que está na branch correta:
     bash
     git branch
     
   - A branch ativa será marcada com um *.

---

### *Adicionando e Comitando Alterações*
1. *Verifique Alterações no Repositório*:
   - Veja quais arquivos foram modificados:
     bash
     git status
     

2. *Adicione os Arquivos ao Commit*:
   - Adicione todas as alterações feitas:
     bash
     git add .
     
   - Ou adicione arquivos específicos:
     bash
     git add nome-do-arquivo
     

3. *Faça o Commit das Alterações*:
   - Crie um commit com uma mensagem descritiva que explique o que foi alterado:
     bash
     git commit -m "Descrição clara das alterações feitas"
     

---

### *Subindo Alterações para o Repositório Remoto*
1. *Envie a Nova Branch para o Repositório Remoto*:
   - Faça o push das alterações na branch para o GitHub:
     bash
     git push origin nome-da-branch
     

2. *Verifique no GitHub*:
   - Confirme se a nova branch aparece no repositório remoto.

---

### **Fazendo o Merge com a Branch main**
1. **Troque para a Branch main**:
   - Certifique-se de estar na branch principal:
     bash
     git checkout main
     

2. **Atualize a Branch main**:
   - Baixe quaisquer alterações que outros membros tenham feito na main:
     bash
     git pull origin main
     

3. *Realize o Merge*:
   - Una sua branch com a main:
     bash
     git merge nome-da-branch
     

4. *Resolva Conflitos (se necessário)*:
   - Conflitos podem ocorrer se alterações forem feitas nos mesmos arquivos. Resolva-os manualmente no editor e continue o merge:
     bash
     git add .
     git commit -m "Resolve conflitos durante o merge"
     

5. **Envie a main Atualizada para o Repositório**:
   - Suba as alterações da main para o GitHub:
     bash
     git push origin main

## *2. Paleta com Todos os Comandos*

| *Comando*                            | *Descrição*                                                                                   |
|----------------------------------------|-------------------------------------------------------------------------------------------------|
| git --version                        | Verifica se o Git está instalado e mostra a versão.                                            |
| git config --global user.name "Nome" | Configura seu nome no Git.                                                                     |
| git config --global user.email "E-mail" | Configura seu e-mail no Git.                                                                   |
| git clone URL_DO_REPOSITORIO         | Clona o repositório remoto para sua máquina local.                                             |
| git branch                           | Lista todas as branches locais e indica qual está ativa.                                       |
| git checkout -b nome-da-branch       | Cria e troca para uma nova branch.                                                            |
| git status                           | Mostra o status dos arquivos modificados no repositório local.                                |
| git add .                            | Adiciona todas as alterações feitas aos arquivos para o próximo commit.                       |
| git add nome-do-arquivo              | Adiciona arquivos específicos ao próximo commit.                                              |
| git commit -m "Mensagem"             | Cria um commit com a mensagem de descrição das alterações.                                    |
| git push origin nome-da-branch       | Envia (faz o push) da branch local para o repositório remoto.                                 |
| git checkout main                    | Troca para a branch principal (main).                                                       |
| git pull origin main                 | Atualiza sua branch main com as alterações mais recentes do repositório remoto.             |
| git merge nome-da-branch             | Integra as alterações de uma branch à branch ativa (normalmente main).                      |
| git push origin main                 | Envia (faz o push) as alterações da branch main para o repositório remoto.                  |

| *Tarefa*                                         | *Comando*                                 | *Quando Usar*                                                                            |
|----------------------------------------------------|---------------------------------------------|--------------------------------------------------------------------------------------------|
| Configurar nome e e-mail no Git                   | git config --global                      | Apenas na primeira configuração da máquina local.                                           |
| Clonar o repositório                              | git clone                                | Sempre que for baixar o repositório remoto para a máquina local pela primeira vez.         |
| Criar uma nova branch                             | git checkout -b                          | Antes de começar uma nova funcionalidade ou corrigir um bug.                               |
| Adicionar alterações                              | git add                                  | Após modificar ou criar arquivos, antes de fazer o commit.                                 |
| Fazer o commit                                    | git commit -m                            | Para salvar as alterações localmente com uma mensagem descritiva.                          |
| Enviar as alterações para o repositório remoto    | git push origin                          | Após finalizar as alterações na branch e fazer o commit.                                   |
| Atualizar a branch local                          | git pull origin                          | Antes de fazer um merge com a main, para garantir que sua branch esteja atualizada.      |
| Fazer o merge de uma branch com a main          | git merge                                | Após concluir uma sprint ou funcionalidade e verificar que tudo foi testado corretamente.  |
| Resolver conflitos                                | Resolve manualmente + git add + commit | Quando o Git apontar conflitos durante um merge.                                           |

3.Como trabalhar com repositórios clonados de forma errada

Ah, entendi! Isso é o comportamento normal do git clone.

Quando você clona um repositório, o Git:

Baixa todos os dados (histórico completo, commits, branches, tags) do repositório remoto.
Cria uma cópia local desses dados.
Configura o controle remoto padrão, geralmente chamado origin, apontando para o URL de onde você clonou.
Cria um único branch local, que é o branch padrão do repositório remoto (geralmente main ou master), e define ele como o branch ativo (HEAD).
As outras branches não são criadas automaticamente como branches locais. Elas existem no seu repositório local como branches de rastreamento remoto (remote-tracking branches). Pense nelas como ponteiros para o estado das branches no momento do clone, no controle remoto origin (por exemplo, origin/develop, origin/feature/nova-func).

Como acessar e trabalhar em outras branches:

Para começar a trabalhar em outra branch, você precisa criar um branch local a partir da branch de rastreamento remoto e "checkar" para ela.

Veja todas as branches disponíveis (locais e remotas):
Execute este comando para listar todas as branches. As branches locais aparecerão sem prefixo, e as branches de rastreamento remoto aparecerão com o prefixo remotes/origin/.

Bash

git branch -a
Você verá algo como:

* main
  remotes/origin/HEAD -> origin/main
  remotes/origin/develop
  remotes/origin/feature/nova-func
  remotes/origin/outra-branch
O * indica a branch local onde você está atualmente (main).

Crie um branch local a partir de uma branch remota e mude para ele:
Use o comando git checkout seguido do nome da branch remota (sem o remotes/origin/). O Git é inteligente e, se você der um checkout em um nome de branch que existe no remoto (como develop), mas não localmente, ele automaticamente criará um branch local com o mesmo nome que rastreia a branch remota correspondente.

Por exemplo, para trabalhar na branch develop:

Bash

git checkout develop
Se a branch develop existir no remoto (origin/develop), o Git criará um branch local chamado develop que rastreia origin/develop e mudará para ele. Você verá uma mensagem como:

Branch 'develop' set up to track remote branch 'develop' from 'origin'.
Switched to a new branch 'develop'
Agora, se você executar git branch (sem o -a), verá suas branches locais, incluindo a develop:

Bash

* develop
  main
Pronto! Você pode repetir o Passo 2 para cada branch que você queira ter uma cópia local para trabalhar. A cópia completa do histórico de todas as branches já está no seu computador desde o clone. Você só precisa "materializar" as branches locais que deseja usar.




4.Voltando para commits anteriores.

🔁 1. Voltar temporariamente (sem alterar histórico)
Use quando você quer ver ou testar um commit antigo, mas sem mudar a linha do tempo do projeto.

bash

git checkout <hash-do-commit>
Isso te coloca em um "modo detached HEAD" (fora de qualquer branch).
Para voltar depois, use:

bash

git checkout main  # ou outra branch
🔙 2. Voltar permanentemente (resetar o histórico)
Use quando você quer que sua branch realmente volte a um commit anterior, apagando commits mais recentes:

bash

git reset --hard <hash-do-commit>
⚠️ Perigoso: commits após esse ponto serão perdidos (a menos que estejam em outro branch ou reflog).

🧹 3. Desfazer commits mas manter alterações nos arquivos
Use quando quer desfazer commits mas manter o código modificado:

bash

git reset --soft <hash-do-commit>
Ou:

bash

git reset --mixed <hash-do-commit>  # Apaga os commits e joga as alterações para staging area
🔁 4. Criar um novo commit que desfaz um anterior (sem apagar histórico)
Use quando você quer "voltar atrás" sem apagar o histórico (ideal para branches compartilhadas):

bash

git revert <hash-do-commit>
Cria um novo commit que desfaz as mudanças do commit informado.

Como ver o hash dos commits anteriores

Você pode ver o hash dos commits com o comando:

bash

git log
Esse comando mostra o histórico de commits, incluindo:

O hash completo (começa com commit abc123...)

O autor

A data

A mensagem do commit



5.Para ver apenas o hash e a mensagem do commit:

Se quiser ver só os hashes curtos e as mensagens, use:

bash

git log --oneline
